# Stylist 3.0

Based only on the verified deployed v195 branch. Its original source hash is
`820bbdf336d7d48cebc0e7415618fc437618a644cabc1e97d2014ee86bb15552`.
The dirty primary checkout is untouched.

One shared planner now owns bounded construction, whole-outfit evaluation,
physical identity matching, shoe selection/rotation and the feasible seed.
Compatibility exports delegate to that planner. Metadata on immutable request
rows, directional layer pairs and full-look verdicts are cached. The provider
ranks at most nine complete alternatives once (no retry); failure retains the
validated deterministic seed. Returned products are never reconstructed after
ranking. Exact identity matching over the bounded reserve and a compatibility
bitset fallback prevent secondary variety preferences from rejecting an already
available feasible triple. Exploration remains bounded; no global catalog
feasibility claim is made from a partial search.

Versioned metadata-only garment intelligence is stored additively in a separate
RLS table. Original catalog rows, prices and ownership are unchanged. Confidence
and unknown values are retained; no image/provider enrichment runs at generation
time. Source changes invalidate cached attributes. Both mobile and Edge use the
same invoker-RLS indexed discovery RPC, including native budgets and server-only
request-scoped FX. The normal legacy scan and missing-capability fallback are
removed. Original catalog/wardrobe RLS and critical financial/auth gates remain.

Positive formulas remain soft. Whole-look scoring now measures motif hierarchy
and whether upper/lower dress registers have a styling bridge, with existing
quality floors. No new product-specific exceptions. Climate remains unknown
when temperature is unavailable.

Privacy-safe diagnostics contain stable failure code/stage, counts, synchronous
segment timings and separate catalog/provider wait timings. The synchronous
planning guard stops exploration with headroom. These timings are not a claim
of measured Supabase CPU usage. Automatic client provider/history retries and
silent local recovery after a failed new generation are removed. Versioned
immutable server plans are validated by the client without local reconstruction.

Confirmed from code: repeated quality work, bounded exhaustive post-selection
shoe assignment, and a separate rotation-failure 422 path. The exact exhausted
production stage and historical 422 codes remain unconfirmed. New diagnostics
support owner verification; neither CPU reliability nor visual quality is
claimed before that verification.

Minimal checks: changed dependency graph TypeScript; frozen-lock Edge Deno;
PostgreSQL migration/RLS, write denial, bounds, search, FX and invalidation;
three actual-handler safety cases with mocked provider. No broad regression,
CPU campaign, simulator automation or paid inference. Release tooling archives
exact v195 source, gates committed inputs and catalog activation, and checks
post-deploy source hash and authentication. Optional catalog-capability rollback
runs only after restoring v195; prior v194 rollback artifacts remain intact.
