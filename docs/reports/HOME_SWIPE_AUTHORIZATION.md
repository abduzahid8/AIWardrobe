# Home swipe authorization — 25 October 2026

Home previously advanced/saved/skipped the card after a synchronous cache check and sent the quota increment in the background. Rapid gestures could therefore advance additional cards before the server's exhausted counter arrived. Awaiting the old callback after the fly-off animation would leave the current card off-screen while the network was pending.

The source now checks the allowance before the fly-off animation. The current card stays visible with a loading indicator; a synchronous ref blocks duplicate gesture/button decisions. Server denial, verification failure, card replacement and unmount do not commit the card action. Replacing the card or unmounting the stack aborts cooperative transport and prevents obsolete paywall/error navigation. The save/skip callback runs after approval and animation, without another local gate or duplicate quota increment.

Home requests server confirmation even while trial UI status is pending. This path never substitutes a cached offline allowance for failed verification. Other callers retain their existing offline behavior. Server-approved Home actions do not await best-effort cache storage. Writes remain ordered and owner-scoped; unchanged counters avoid redundant writes. Quota labels subscribe to the counter snapshot rather than only stable getter functions.
