# Stylist 2.0

Implemented directly on verified ACTIVE v194 (404c4b0). A fresh v194 bundle and
its downloaded deployed original both hash to
`afa771ffa85780f5c45490dc0e2b8d17943fa8bb90d989defe1fa19795e00dfe`.
The dirty primary checkout was not used or modified.

The existing deterministic domain kernel now carries positive style formulas
through catalog representatives, bounded quartet construction, whole-outfit
scoring, the NVIDIA shortlist and final joint deck selection. Classic prioritizes
tailoring; Old Money prioritizes Ivy knit relationships; Semi-Classic prioritizes
modern tailoring; Casual prioritizes relaxed layers. Alternative formulas and
the generic compatibility beam keep creative combinations available. Formulas
are soft preferences and never waive an existing acceptance rule.

Retrieved rows compete within a narrow quality band on documented subtype,
color, fit, pattern and texture. Nearly identical listings no longer consume all
representative positions. Affordable per-slot floors and physical identity
checks remain authoritative. The same request context (including preferences
and weather) now reaches catalog scoring, rather than reconstructing context
from prompt text. Structured fit, silhouette, layering, purpose and occasion
metadata can provide evidence. Missing visual attributes stay unknown; studio
background text cannot establish garment color or pattern.

Construction shares the existing beam among style intentions and retains both
styling-role coverage and independent products. The existing coherence scorer
rewards the strongest complete formula, including its weakest relationship.
The existing NVIDIA call receives compact descriptors and complete-look intent.
The shortlist and final deck compare actual styling changes. Within the quality
band, improving the weakest pair's styling difference precedes provider rank;
rotation, physical uniqueness, protected good looks and quality remain prior
constraints. Sparse inventory can still have limited meaningful variation.

No new model calls, catalog queries, schema changes or new outfit engine.
Existing 40-item pool, 384 proposal-attempt limit, 48 admitted quartet reserve,
24 complete choices, nine NVIDIA options and 512 deck-search steps remain.
Auth, quota, subscriptions, source/ownership, budget/FX, four slots, anchors and
shoe rotation retain their existing authority. The release script additionally
compares critical function bodies to v194 before preparing a release.

Verification uses existing focused checks, four new domain checks and one new
actual-handler fixture. See checks.json. No paid inference, visual test batches
or authenticated production generation were run. Automated and offline results
establish engineering behavior; visual quality acceptance remains with the
owner's iOS Simulator testing and production log inspection.

Release only `generate-outfits` using `scripts/validation/stylist-2-release.cjs`:
`prepare` checks live v194 and saves exact rollback source; `deploy` requires
pushed committed inputs and unchanged production baseline; `verify` downloads
and hashes deployed original source, checks ACTIVE/auth and other functions,
and probes OPTIONS/missing/invalid authorization. `rollback` restores v194
only after checking the current release fingerprint and archive hash. Supply
`SUPABASE_ACCESS_TOKEN` or `SUPABASE_ACCESS_TOKEN_FILE`; credentials are never
written to release artifacts. Existing rollback releases are preserved.
