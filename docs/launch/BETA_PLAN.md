# Controlled beta and release gates

All stages are plans, not activated cohorts. Record a named release owner, support contact selected by the team, privacy notice, approved per-feature spend cap and observer rota before invitations. Feedback is voluntary; use the reviewed local export until a separately approved destination is available. No target baselines are invented here.

Success requires a user outcome: generated outfit saved/worn; BuyCheck explicitly helpful; duplicate purchase explicitly avoided; usable missing piece confirmed; recreated look saved and confirmed successful; fit later confirmed; or return on another day to plan an outfit. Open/view/scroll counts are exposure context only. Do not infer avoidance from an absent purchase event or fit confirmation from a synthetic try-on render.

Elapsed observation windows alone do not satisfy an exit gate. Small samples are reported with counts, uncertainty and missing data. A stage that produces no confirmed value is not successful because it did not crash. No numeric retention/conversion target is claimed before a cohort baseline exists; the owner may define a prospective threshold and record its version before exposure.

GO checklist (all mandatory): zero security/data/startup BLOCKER; no known data-loss path; premium restore/subscription reliable if exposed; core generation stable; BuyCheck hard constraints pass; reversible migration exposure and verified recovery; acceptable installed old/new combinations; real effective kill and cost caps; required device/manual QA complete; known limits communicated; named owner and monitoring ready. NO-GO on cross-user leak risk, migration uncertainty, repeated startup crashes, unreliable billing, hard-rule AI violations, essential remote provider without fallback or serious privacy issue. The current packet is NO-GO pending these external proofs.

After the first users, every significant change starts with a ticket: problem → dated evidence/sample/RC/cohort → hypothesis → smallest change → effective flag/rollback → prospective metric/guardrail → approved rollout → observed result → keep/revert. Answer the eight scope questions in FEEDBACK.md before proposing large features. No feature speculation replaces those answers.
