Performance measurement plan: use the SAME pinned release, synthetic fixtures and network conditions before/after. Capture 10 cold and 20 warm runs where practical; report p50 and full range with sample count. Clear OS launch state for cold runs without deleting user fixtures. Use Instruments/Xcode launch metrics and Android Studio/Perfetto for startup/frame/heap; existing perfMark/perfMeasure/perfAction are opt-in diagnostics and may measure different boundaries. For client generation/BuyCheck overhead isolate request preparation/render work from provider/network duration. Never report provider RTT as client overhead or JS export size as startup speed.

| Metric | Boundary / proposed engineering gate (not measured baseline) |
|---|---|
| Cold/warm startup | launch intent → interactive core screen; no crash, auth deadlock or indefinite splash; proposed p50 <=5s cold / <=2s warm on older target |
| Home/wardrobe/Shop paint | navigation → first usable content or truthful cached/empty state; proposed p50 <=2s for cached content |

These are initial proposed stop conditions; release owner signs them before execution and may tighten them from measured evidence. Blank metrics are unknown, never zero or production claims. Use performance-results.csv.

Stress procedure: `npm run beta:personas` yields five personas plus 220-item and 24-reference fixtures without writing remotely. Import only through a local/mock fixture adapter; this file is not a production seed script. Native run: load 220 items; import/delete 30 selected images repeatedly; scroll 5 minutes; load 24 references; generate 25 times with mock provider; open 20 mock VTON history entries; perform 10 background/foreground cycles and a memory warning. At each stage record heap/RSS, image cache usage/eviction, long frames and crashes, then idle 60 seconds. Repeat three cycles; investigate monotonic retained growth. Do not draw a native leak conclusion from Node heap without GC.

The host stress suite calls real BuyCheck 25 times over 220 synthetic items and checks metadata-cache eviction (300 max), 350 reference metadata insertions, and outfit board snapshot bounds (10 max). evidence/host-stress.json records host p50/range/heap delta. It does NOT test native image import/decoding, real long scrolling, VTON image history or OS memory pressure; those rows remain manual. No native memory/performance gate can be marked PASS from that host report.
