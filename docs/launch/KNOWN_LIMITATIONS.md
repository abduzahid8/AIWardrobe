# RC known limitations

- The working tree includes substantial preexisting local work. The generated manifest fingerprints it; no commit/push or remote activation occurs here.
- Full authenticated device QA, approved-config native client installation, four-class performance/image-memory testing and sandbox restore remain unexecuted for this RC. The actual App root was additionally checked signed out/offline with native billing/sending/background prewarm disabled; OFFLINE_APP_QA.md records the limited startup/language/sign-in-failure evidence. A separate isolated Release harness was installed, benchmarked, stress-tested and used to verify feedback UI on one simulator; NATIVE_LOCAL_QA.md explains why those limited receipts do not close the full-app gates. Historical receipts are not reused as current proof.
- Local Postgres tests cover six pending local migrations on bounded synthetic baseline fixtures, not the hosted migration ledger or a complete Supabase stack. Hosted schema drift/backup recovery/PostgREST visibility must be verified after explicit approval.
- Platform boolean flag helpers are not universal caller controls or remotely persistent switches. Advanced routes remain unapproved; shared server-stop code for six metered Edge entries is locally verified, but deployed controls, legacy route coverage, provider denial, quotas and rollback must be drilled before beta.
- Feedback is an optional reviewed JSON share path, not an automatically delivered support system. Drafts/correction assertions are session-local and discarded on close/account change; user chooses export for audit. Corrections do not automatically repair shared catalog data or retrain AI.
- BuyCheck has local diagnostic metadata, but not every outfit/legacy recommendation has request/trace correlation. Missing fields are omitted instead of fabricated.
- Telemetry is partial. Existing analytics flush acknowledges a log endpoint; no dashboard/alerting destination or cross-process exactly-once sink is installed. eventId supports downstream dedupe; retries are at-least-once. Native startup/crash and many value outcomes still need instrumentation validation.
- Node BuyCheck p50/heap and metadata-cache stress are host diagnostics only. The isolated native fixture exercises local original-image decode/cache/scroll and synthetic history, but production image-picker/thumbnail/history components and physical OS pressure remain unmeasured.
- No real-user outcomes, retention, willingness-to-pay, cost or purchase avoidance baseline exists. Zero reports do not establish zero problems.
- The reviewed offline catalog seed can be stale and prices are not current checkout evidence. Sparse Fit/Style/price evidence must remain unknown/low confidence. Four-slot styling still requires a layer; no-jacket wording does not relax the current structural contract.
- iOS 65/Android 63 are local build identities; store uniqueness and signed artifact readiness are unverified. JS export does not certify App Store/Play Store acceptance.
- Deno was located under ~/.deno/bin; the current report records pinned-lock Edge typechecking. Local handler mocks/typechecking are not equivalent to deployed Deno validation.
- An old document contained a Google-key-shaped value. Local redaction and worktree scanning do not prove historical removal or credential rotation; the owner must classify it and approve any remote rotation.

- Native baseline receipts predate the later server-stop/client error-classification patch. Entry/feedback/startup source hashes are preserved; these limited measurements do not certify a newly signed final client or the new 503 path on a device. The 503 decoder and fallback rules are verified by local contract tests.
